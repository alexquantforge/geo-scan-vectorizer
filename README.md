# geo-scan-vectorizer
Vectorizes Soviet-era geological scans (24030×13244) to DXF/DWG: tiled skeleton + LSD wavy horizons, short tics & dotted fills, with multimodal REL fallback.

## Pipeline
- Input: `original_scan.jpg 24030×13244` (upper 24030×6778 geological + lower technological)
- Tiling: 5×4 = 20 tiles 4806×3311 via `vips crop`
- Per tile: skeleton 1px (adaptiveThreshold 101,12 + iterative thinning) → wavy green; LSD 12-50px ±18° → short red tics; Otsu fat dots 15-110px → purple
- Assembly: `vips arrayjoin` → `assembled_lines_white_vips.jpg 13M` + preview 10% + overlay 40/60
- Example: `r1c1_22_green_purple.jpg` (1001×847) — 203 straight + 564 curved + 42 fat dots 1:1

## Usage
```bash
vips crop original.jpg tile.jpg x y w h
python scripts/process20b.py  # 20 tiles
vips arrayjoin ... --across 5
```

## Полный цикл: скан → 20 тайлов → таблицы и overlay по подпапкам

`scripts/vectorize_scan.py` за один запуск делает всё: режет скан на сетку
**10 столбцов × 2 ряда = 20 тайлов** (10 сверху и 10 снизу), прогоняет по ним
детектор из `scripts/detect_lines.py`, собирает каждый ряд из 10 тайлов в одну
полосу и раскладывает результаты по подпапкам.

```bash
python -m pip install -r requirements-detection.txt -r requirements-tiles.txt
python scripts/vectorize_scan.py "/путь/к/РЛ-III(Г).jpg"
```

Путь к скану можно не указывать, если он совпадает с `DEFAULT_IMAGE` в скрипте.
Результаты по умолчанию пишутся в соседнюю папку `<имя скана>_vectorized`:

```
РЛ-III(Г)_vectorized/
  tiles/row_01/…           10 тайлов верхнего ряда (PNG, имя x0_y0_x1_y1)
  tiles/row_02/…           10 тайлов нижнего ряда
  rows/row_01.jpg          верхние 10 тайлов, склеенные в ряд
  rows/row_02.jpg          нижние 10 тайлов, склеенные в ряд
  tables/tiles/row_01/<тайл>.csv, .json   координаты по каждому тайлу
  tables/tiles/row_02/…
  tables/rows/row_01.csv, .json           сводка по ряду
  tables/rows/row_02/…
  tables/lines.csv, lines.json            все объекты в координатах скана
  tables/tiles_summary.csv                одна строка на тайл + счётчики
  overlays/tiles/row_01/<тайл>.jpg        overlay каждого тайла (20 файлов)
  overlays/tiles/row_02/…
  overlays/overlay_full.jpg               общий overlay на весь скан
  overlays/overlay_preview.jpg            уменьшенное превью общего overlay
  run.json                                параметры запуска, карта тайлов
```

Особенности:

- Координаты в таблицах глобальные (от левого верхнего угла скана), а рядом
  добавлены локальные `x1_local, y1_local, x2_local, y2_local` в пикселях тайла.
- Имена тайлов сохраняют схему `x0_y0_x1_y1.png` с включительными границами.
- Ряды и столбцы кратны ширине/высоте скана, поэтому границы тайлов могут
  отличаться от круглых чисел (например, 2403 px), но покрытие полное и без
  наложений.
- Повторный запуск в существующую папку требует `--overwrite`; программа
  удаляет только созданные ею подпапки `tiles/`, `rows/`, `tables/`, `overlays/`
  и файл `run.json`, а при посторонних файлах останавливается.
- Полезные ключи: `--columns 10 --rows 2` (другая сетка), `--output-dir`,
  `--no-row-strips`, `--preview-max-side`, `--dot-window-stride`, `--jobs N`.
- `--jobs N` обрабатывает N тайлов параллельно в отдельных процессах: на
  4 ядрах полный скан идёт примерно в 3–4 раза быстрее, но каждый процесс
  держит один тайл в памяти. По умолчанию 1 (последовательная обработка).
- Один тайл 2403×6622 обрабатывается примерно 30 с, то есть весь скан —
  порядка 10 минут на одно ядро.
- Новый режим ничего не меняет в прежних сценариях: `split_scan_tiles.py`,
  `detect_lines.py` и `detect_tile_lines.py` работают как раньше и дают
  побайтово те же `lines.json`/`lines.csv`/`overlay.jpg`; старые вызовы
  `detect_tiles(tiles, width, height, 500)` остаются валидными.

Детектор для тайлов произвольной геометрии вызывается так:

```python
from scripts.detect_tile_lines import Tile, detect_tiles

records = detect_tiles(tiles, width, height, grouping_stride=2000)
```

## Разбиение скана на тайлы 500×500

Для отдельного разрезания изображения установите Pillow:

```bash
python -m pip install -r requirements-tiles.txt
```

Запуск без аргументов использует путь к `РЛ-III(Г).jpg`, указанный в `scripts/split_scan_tiles.py`. Либо передайте путь явно:

```bash
python scripts/split_scan_tiles.py "/home/alex/2025-12-03-1636-backup/PycharmProjects/geo-scan-vectorizer/Графика_разрезы/Графика_разрезы/РЛ-III(Г).jpg"
```

Рядом с исходником будет создана папка `РЛ-III(Г)_tiles_500_by_500`. Тайлы сохраняются в PNG без повторного JPEG-сжатия. Формат имени — `x0_y0_x1_y1.png`; четыре числа — координаты первого и последнего пикселя тайла **включительно**, начало `(0, 0)` находится в левом верхнем углу. Например, первый тайл: `00000_00000_00499_00499.png`. Краевые тайлы справа и снизу будут меньше 500 пикселей, без искусственного дополнения.

Если папка с результатом уже существует и не пуста, скрипт остановится, чтобы не перезаписать файлы. Для явной пересборки добавьте `--overwrite`.

## Поиск линий на тайлах и наложение на скан

Установите OpenCV и NumPy:

```bash
python -m pip install -r requirements-detection.txt
```

Запуск без аргументов использует указанный в скрипте `РЛ-III(Г).jpg` и соседнюю папку `РЛ-III(Г)_tiles_500_by_500`:

```bash
python scripts/detect_tile_lines.py
```

Либо передайте путь к скану и, при необходимости, к папке тайлов:

```bash
python scripts/detect_tile_lines.py "/путь/к/РЛ-III(Г).jpg" --tiles-dir "/путь/к/РЛ-III(Г)_tiles_500_by_500"
```

Скрипт использует детектор из `scripts/detect_lines.py`, переводит локальные координаты тайлов в координаты исходного изображения и сохраняет в соседнюю папку `РЛ-III(Г)_line_detection/`:

- `lines.json` и `lines.csv` — найденные объекты и их координаты в пикселях от левого верхнего угла исходника;
- `overlay.jpg` — полноразмерный исходник с обнаруженными объектами;
- `overlay_preview.jpg` — уменьшенное превью для быстрой проверки.

Цвета наложения: `straight` — красный, `curved` — зелёный, `dashed_curve` — пурпурный, `small_circle` — жёлтый, `aligned_dot` — белый с чёрной каймой. Маленькие круговые символы распознаются как тонкая замкнутая тёмная кайма вокруг круглого светлого центра с достаточным контрастом; если касающийся штрих искажает внешний контур, дополнительный проход проверяет светлое круглое отверстие и окружающий его тёмный обод. Сплошные точки, кольца с тёмной серединой, мелкие шумовые кольца и вложенные повторные контуры не попадают в тип `small_circle`.

Отдельный проход отмечает каждую компактную тёмную метку типа `aligned_dot`, только если не менее шести центров образуют почти прямой ряд с примерно одинаковым шагом. При наличии линейных сегментов ориентация ряда ограничивается их доминирующим направлением (допуск 10°), а без сегментов оценивается по кандидатам; проверка шага допускает до двух пропущенных промежуточных меток (разрыв до трёх шагов), а шаги между найденными метками после нормализации должны укладываться в отклонение от медианы не более 22% и коэффициент вариации не более 15%. Поперечный допуск — 6 px, базовый шаг — от 40 до 170 px, минимальный размах ряда — 40 px. Фрагменты одной метки объединяются до подсчёта; компактные кандидаты ищутся при пороге серого уровня ≤100. Метки ближе 15 px к найденному линейному сегменту (для крупных меток порог увеличивается) исключаются безусловно, даже если в нём видны разрывы; оставшиеся точки образуют отдельный ряд с отступом от линий. Поиск точечных рядов выполняется в глобальных окнах, отбрасывает центры за границами исходного изображения и может пересекать границы тайлов 500×500. Каждая точка получает отдельную круговую отметку без соединяющей линии. Поля `x1` и `y1` содержат глобальный центр, `radius` — радиус подсветки в пикселях, `x2` и `y2` повторяют центр, а `length` содержит длину окружности. У линейных типов `radius` пустой (`null` в JSON). Синие/голубые пиксели маскируются до поиска, но тёмные почти нейтральные пиксели сохраняются, чтобы не стирать чёрный штрих с цветного фона; прежняя оранжевая эвристика `dashdot` не используется. Новый `dashed_curve` отдельным проходом связывает тёмные компоненты, если они образуют плавную наклонную цепочку; выраженные горизонтальные/вертикальные линии сетки подавляются перед группировкой. Обычные сегменты по-прежнему проверяются по поддержке тёмными пикселями (серый уровень ≤110, минимум 35% точек линии с допуском 3 px). Это эвристика формы, не геологическая классификация: ложные срабатывания всё ещё возможны; линейные сегменты через границы тайлов могут оставаться раздельными.

